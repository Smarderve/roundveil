## Emergency recovery — Batch A (2026-10-11)
- Reproduced the Quick Game editor crash: its pushed route mounted `CinematicSessionBuilderPage` without a `Scaffold`/`Material` ancestor, so its session-name `TextField` threw `No Material widget found`. The Quick Game edit route now provides `Scaffold` + `SafeArea`.
- Reproduced the compact-width layout error: below 720 px, `_ModuleForge` (`Expanded` grid) and `_SquadForge` (`Spacer`) were placed inside a vertical `SingleChildScrollView`, giving their `Column`s unbounded height. The compact branch now gives both panels finite heights inside the scrollable. The same test also guards the reported extreme overflow regression.
- Focused widget tests now cover editing a Quick Game template and rendering the builder at 640×360. Full `flutter test` passes **33 tests**, `flutter analyze` reports no issues, and `git diff --check` passes.
- Android debug APK built and installed on the existing landscape emulator. The app launched, and live taps reached Quick Game → template preview → edit screen. Relevant `logcat` filters contained no Material-ancestor, Flutter rendering overflow, or fatal-startup errors. Evidence: `docs/evidence/emergency_recovery_2026-10-11/android_launched.png`, `android_quick_page.png`, and `android_quick_editor.png`.
- Limitation: focusing the editor on this emulator opened Android's “Try out your stylus” handwriting guide instead of a conventional keyboard, so physical keyboard/text entry was not verified on-device. Widget-level text entry passed; no input-method workaround was applied.
- This closes Batch A only. ROUNDVEIL is **not launch-ready**: five modules still lack complete playable loops, requested offline-content targets are unmet/unverified, and Windows runtime rendering remains blocked as documented below.

## Current blockers
- Milestone 1 still needs a real Flutter-integrated 3D proof on both Windows and Android (visible rigged model, camera input, skeletal animation and runtime appearance change) before a renderer can be selected. Windows requires a policy-approved execution environment; Android still needs SDK Platform 33 setup completed and a compatible ARM64 runtime. No renderer investigation or production avatar work was part of this shell task.
- The current Guess the Country choice/typed-answer candidate conflicts with the new directive; target mechanics are now flag-only, spoken answer and host reveal/judgement. The implementation and its old tests have not yet been migrated.
- Local configuration drafts, shell locales and theme switching now exist, but profile/session databases, persistent preferences, recoverable gameplay runtime, complete gameplay translation coverage and production content targets remain unimplemented. See the shell foundation note and rebuild audit.
- The prior avatar-lobby candidate is not approved as final platform UX. Its historical native Windows screenshot gap remains unverified; it does not block the newly authorized rebuild.
- Windows gameplay-state rendering remains unverified; only the native opening state was exercised and captured on Windows. Android gameplay and desktop/mobile widget renders passed.
- Exact future game variants/scoring defaults, family-friendly age settings and hosting model still need decisions.
- The Android SDK and licenses are healthy. The required NDK r28c (`28.2.13676358`) and Android Platform 36 were installed into the existing SDK during verification. Flutter/Dart executables remain outside the persistent PATH, but the verified local Flutter SDK is used directly; this is a convenience warning, not a build prerequisite.
- Codex Windows builds require a **temporary, command-process-only** Java setting: `JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=C:\\Windows\\Temp`. It was not made permanent. See `docs/architecture/ANDROID_BUILD_ENVIRONMENT.md` for exact use/removal instructions and limits.
- The required outside-Codex PowerShell control has not been run. It remains useful to confirm whether the setting is unnecessary in a normal terminal; it is not a blocker for the verified Codex build/emulator result.
- Guess the Country needs product resolution for its default inclusion policy, any curated-extension membership, and the eventual gameplay UX before production implementation. An official complete flag pack must be legally/source reviewed and visually audited before assets ship.
